# Devlog 027 — Rediseño UI estilo Anno/Northgard (solo presentación)

## Objetivo
Convertir los paneles oscuros genéricos con listas planas en un HUD de
estrategia moderno (referencia Anno 1800 / Northgard) sin tocar ningún flujo
de datos ni el puente `window.__game`.

## Leído antes (AGENTS.md)
- `src/app/play/page.tsx` entero (flujos stock/selected/roadMode/inspect/
  stalls/pop/rival/music/objectives/ending + puente `window.__game`).
- `src/components/GameCanvas.tsx`, `src/app/globals.css`,
  `src/game/data/buildings.ts` (nombres, costes, categorías).
- Guías Next 16 en `node_modules/next/dist/docs/`: upgrade v16
  (sin breaking changes para esta UI: seguimos con `'use client'`,
  `<img>` + `Link`, Tailwind vía `@import "tailwindcss"`), CSS e imágenes
  (se mantienen `<img>` con onError-fallback; no se adopta `next/image`
  para no cambiar el comportamiento de fallback parpadeante).

## Cambios (solo presentación)
- **`src/components/hud-icons.ts` (nuevo)**: PACK/ORDER/iconFor/
  iconFallback/resIconFor/onImgFallback con la lógica idéntica a la que
  tenía `play/page.tsx` + metadatos de categorías (glifo+etiqueta).
- **`src/components/HudPanels.tsx` (nuevo)**: `TopBar` (sticky, blur),
  `ResourceBar` (tira compacta con iconos, scroll-x en móvil),
  `ColonyPanel` (objetivos con barra de progreso + población + paradas,
  mismo contenido y condiciones que antes, diseño de tarjeta unificado),
  `InspectCard` (tarjeta con borde ámbar/rojo, distintivo ⚔ Rival,
  receta, faltantes, recluta en cuartel), `EndingOverlay` (victoria/
  derrota pulida, mismos textos/stats/botón reload).
- **`src/components/BuildMenu.tsx` (nuevo)**: muelle de construcción con
  pestañas por categoría (Todo/Base/Madera/Piedra/Comida/Minas/Industria/
  Militar/Mar/Ornato, con conteos), tarjetas con icono, coste con
  iconitos de recurso (rojo si falta stock — solo visual) y
  `title` ampliado (descripción + coste + tiempo de obra). Botón 🛤 Camino
  siempre visible en la cabecera del muelle, con el mismo handler y tooltip.
- **`src/app/play/page.tsx` (edit)**: mismos estados, mismos intervalos
  (1000 ms juego / 5000+3000 ms guardado), mismas llamadas
  (place/road/save/load/recruit) y mismos `<img onError>`; solo cambia el
  layout: cabecera sticky, barra de recursos, grid mapa+inspect / lateral
  (estado + guía del colono), muelle de construcción, footer de créditos.
- **`src/app/page.tsx` (edit)**: landing con hero ámbar-sobre-verde-noche,
  CTAs y enlaces intactos, mismas capturas y créditos; añade tira de stats
  y tarjetas de cadena productiva (solo CSS, sin assets nuevos).
- No se tocó `src/game/`, `GameCanvas.tsx` ni `globals.css`. Sin assets de
  terceros: solo se reutilizan `/assets/wl/icons/*.png` + glifos/emoji.

## Verificación
- `npx tsc --noEmit`: limpio.
- `npm test` (vitest): en verde.
- `npm run build`: en verde.

## Deuda / autocrítica
- La tira de recursos usa scroll horizontal en móvil en vez de un colapsable
  más elegante; con 16 recursos sigue exigiendo deslizar.
- Sin modo claro ni densidad configurable; el HUD asume pantalla ≥360 px.
- Los glifos emoji de categorías son texto del sistema (correctos
  legalmente) pero menos "Anno" que iconos dibujados; queda pendiente
  sprite propio si el proyecto quiere sellar la identidad.
